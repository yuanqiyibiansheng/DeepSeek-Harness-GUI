# DeepSeek Harness

[English](README.md) | 中文

DeepSeek Harness（`dsh`）是由 [DeepSeek AI](https://deepseek.com) 开发的开源 agent harness（智能体框架）。

它采用**一切皆插件**的架构，并由 [Cordis](https://github.com/cordiverse/cordis) 驱动，其设计参见论文 [_A Programming Paradigm for Spatiotemporal Composability_](https://github.com/cordiverse/paper)。

## 开发者预览

DeepSeek Harness 目前处于 _开发者预览_ 阶段，正在快速迭代。**未来将出现破坏兼容性的变更。**

## 运行

### 通过 `npm` 运行

安装 `Node.js`，然后运行：

```sh
npx @deepseek-ai/dsh web
```

该命令会启动 Web UI，默认地址为 `http://127.0.0.1:3080`。详见 [Web UI 指南](docs/user/guide/index.md)。

### 从源码运行

如需从仓库源码运行：

```sh
git clone https://github.com/deepseek-ai/deepseek-harness.git
cd deepseek-harness
pnpm install
pnpm run build
pnpm dsh web
```

## 桌面打包

可选的 Tauri 2 外壳可以将 Web UI 打包为 Windows 桌面应用：

```sh
build-desktop.bat
```

脚本会检查 Node.js 22.19+ 或 24+，安装依赖，构建工作区，在 `apps/desktop/bundle` 准备自包含的 `dsh web` 运行环境，并执行 `tauri build`。NSIS 安装包输出到 `apps/desktop/src-tauri/target/release/bundle/nsis/`。

外壳位于 `apps/desktop`，参考了 [NexBox](https://github.com/MuLiuSaMa/NexBox)（GPL-3.0）的 Tauri 外壳布局；应用图标统一使用 `LOGO/DeepSeek256x256.ico` 中的 DeepSeek logo。

## 近期变更

### 自动压缩在本地模型输出上限超过上下文窗口时不再失效

- 修改目标：修复 pi-ai 本地模型未填 `maxTokens` 时自动压缩静默失效——pi-ai 会用 `32_768` 补齐空缺，可能超过手填的更小 `contextWindow`，使 `promptBudget` 变为负数并抛出被步骤监听器吞掉的错误。
- 修改文件：packages/compaction/compaction-basic/src/config.ts、packages/compaction/compaction-basic/tests/compaction-basic.spec.ts、README.md、README.zh.md。
- 修改内容：`resolveCompactSpec` 在 `maxTokens` 缺失或已不小于上下文窗口时，改用整个窗口作为 `promptBudget`，不再抛出 `TargetPressureConfigError`；新增覆盖“输出上限超窗口”降级分支的单元测试。
- 影响范围：报告输出能力等于或超过已配置 `contextWindow` 的本地模型，现在会按正常 80% 阈值触发压缩，而不是永不压缩。
- 注意事项：阈值本身不变；压力监听器仍只在每个目标首次告警后静默，这是另一个可观测性缺口。

### 会话回滚可靠性修复：卡片实时刷新、清空排队消息、原地重载会话

- 修改目标：回滚卡片只在重启客户端后才出现；回滚后旧的排队消息残留在智能体 inbox，发下一条消息时被一并提交；执行回滚强制整页刷新，与参考桌面端“原地重载会话”不一致。
- 修改文件：packages/rewind/session-rewind/src/index.ts（execute 清空智能体 inbox）、packages/client/ui-session-rewind（控制器在已完成回合数变化时重新拉取检查点；卡片改为原地重启后端而非刷新页面）、apps/desktop/src-tauri/src/lib.rs + build.rs + capabilities/default.json + permissions/autogenerated/restart_backend_in_place.toml（新增 `restart_backend_in_place` 命令：同端口重启 dsh 后端且不导航窗口）、README.md、README.zh.md。
- 修改内容：每个完成的回合在回合数变化时重新拉取 `sessionRewind/listTurnCheckpoints`，卡片在回合结束即出现；`execute` 以持久 splice 清空排队与 steering 输入，回滚前的排队消息不会随下一条消息发出；回滚成功后桌面壳在同一端口重启后端，Web 客户端事件流自动重连并原地重基线会话——不再整页刷新，与参考流程一致。
- 影响范围：回滚卡片按回合实时出现；回滚后不会再发送回滚前的排队消息；会话视图原地回退，不再出现整页刷新。
- 注意事项：纯浏览器无桌面壳时仍回退为整页刷新；需重新构建客户端 bundle 与桌面应用后生效。

### 恢复会话回滚界面：回合尾部检查点卡片接入 sessionRewind Remote

- 修改目标：cc-haha 回滚移植只交付了后端服务，前端入口随旧功能一起被移除，界面看不到任何回滚入口；按参考桌面端完全一致的交互恢复——每个完成的回合以「N 个文件已更改」卡片收尾，提供「撤销当前轮次 / 回滚到这一轮之前」。
- 修改文件：packages/client/ui-session-rewind（新增；`conversation.chat.turnTail` 链的 `rewind` 入口 + cc-haha 同款文案与样式 + RewindCard/RewindController 组件与测试）、packages/client/ui-conversation/src/client/skeleton/ConversationSession.tsx（恢复回滚草稿写入输入框的钩子）、packages/bundle/web-app/{package.json,cordis.patch.yml}、tsconfig.client.json、README.md、README.zh.md。
- 修改内容：每个完成的回合从 `sessionRewind/listTurnCheckpoints`（每个会话只读一次）渲染检查点卡片：变更文件数、+N/-M 徽标、可经聊天视图打开器打开的文件行、参考提示文案（检查点不完整时只提供「只回滚对话」，部分覆盖时点名未记录的改动来源）以及参考确认对话框。确认后按所选模式调用 `sessionRewind/execute`，桌面壳原地重启 dsh 服务并让会话视图重基线（不刷新页面）；输入框保持空白，只发送用户接下来输入的内容。
- 影响范围：回滚入口重新可见，布局与参考桌面端一致，完全运行在移植后的 `dsh-session-rewind` 宿主服务上；Rust diff server 保持移除状态。
- 注意事项：依赖上一项 `dsh-session-rewind` 的 zod 依赖修复才能正常启动；需重新构建客户端 bundle 与桌面应用后卡片才会生效。

### 修复回滚移植后的启动报错：补齐 session-rewind 的 zod 依赖

- 修改目标：桌面应用启动时报 `client-modules: require("zod") missed the module table`，原因是 `@deepseek-ai/dsh-session-rewind` 生成的 Typert remote 引用了 zod，但包未声明该依赖。
- 修改文件：packages/rewind/session-rewind/package.json、README.md、README.zh.md。
- 修改内容：在 dependencies 中加入 `"zod": "^4.4.3"`，与所有其他带生成 Typert remote 的包保持一致；zod 可从包自身 node_modules 解析后，tsdown 会将其内联进 api-remotes 客户端包，不再输出 `require("zod")`。
- 影响范围：启动不再因模块表缺失 zod 失败，回滚 remote 与其他生成 remote 一样正常加载。
- 注意事项：需要重新执行 pnpm install、重建客户端 bundle 并重新构建桌面应用后生效。

### 安装器更新前自动关闭正在运行的客户端

- 修改目标：覆盖安装时旧客户端仍在运行，旧进程还在读取被替换的资源，导致下次启动出现 “Failed to load plugins”。

- 影响范围：升级/重装后不再残留旧插件清单或缺失 bundle 脚本错误。
- 注意事项：安装器现在会自动关闭正在运行的客户端；手动关闭后再安装同样安全。
